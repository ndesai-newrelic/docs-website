Our New Relic Flutter agent monitors your Flutter mobile app and provides deep insights into your app's performance, errors, and user experience. Once you install and configure the Flutter agent, you'll be able to:

* <DNT>**Capture and symbolicate Dart errors:**</DNT> Identify and fix problems quickly.
* <DNT>**Track network requests:**</DNT> See how your app interacts with the backend.
* <DNT>**Use distributed tracing:**</DNT> Drill down into handled exceptions and find the root cause.
* <DNT>**Create custom events and metrics:**</DNT> Understand how your users interact with your app.

## (Recommended) Guided installation [#guided-install]

To install the Flutter agent, follow the guided install:
1. Go to <DNT>**[one.newrelic.com](https://one.newrelic.com/) > Integrations & Agents**</DNT>.
2. Search for "Flutter" and click one of the tiles:
    * Flutter: For mobile apps deployed to both Android and iOS
    * Flutter iOS: For mobile apps deployed only to the iOS platform
    * Flutter Android: For mobile apps deployed to the Android platform
    <Callout variant="tip">
    Looking to monitor your web app? Check out [this page](/docs/browser/browser-integrations/flutter-web-integration).
    </Callout>
3. Follow the instructions in the UI to complete installation. 

## Manual installation [#manual-install]

If you need to install the agent manually, follow these steps:

<Steps>
  <Step>
    ### Review the requirements [#requirements]

    Before you install the Flutter agent, make sure your Flutter app meets these version requirements:

    * Flutter 2.5.0 or higher
    * Dart 2.17.0 or higher, up to but not including 4.0.0
    * For Android-native apps:
      * Android API 24 or higher
      * See [Android-native requirements](/docs/mobile-monitoring/new-relic-mobile-android/get-started/new-relic-android-compatibility-requirements)
    * For iOS-native apps:
      * iOS 15.0 or higher
      * See [iOS-native requirements](/docs/mobile-monitoring/new-relic-mobile-ios/get-started/new-relic-ios-compatibility-requirements)

    <Callout variant="important">
      The Flutter agent monitors Android and iOS apps. When you compile your app for Flutter web, the agent's methods compile but do nothing, so no data is reported. To monitor a Flutter web app, see [Flutter web integration](/docs/browser/browser-integrations/flutter-web-integration).
    </Callout>
  </Step>

  <Step>
    ### Add the Flutter agent to your project [#add-agent]

    First, you'll need to add the Flutter agent into your dart project. In your `pubspec.yaml`, add the following to `dependencies`:

    ```yaml
    dependencies:
      newrelic_mobile: ^1.3.2
    ```
  </Step>

  <Step>
    ### Copy your application token [#app-token]

    The application token is used for New Relic to authenticate your Flutter app's data.
    To view and copy your application token in the New Relic UI:

    1. Go to <DNT>**[one.newrelic.com](https://one.newrelic.com/all-capabilities)**</DNT>, click <DNT>**Integrations & Agents**</DNT>, then click <DNT>**Mobile**</DNT>.
    2. Select your Flutter app.
    3. Go to <DNT>**Settings > Application**</DNT> and copy the displayed <DNT>**Application token**</DNT>.

    You'll add this application token in the next step.
  </Step>

  <Step>
    ### Configure your Flutter project [#configure]

    In your Flutter project, open `main.dart` and add the following code:

    ```dart
    import 'dart:io';
    
    import 'package:newrelic_mobile/config.dart';
    import 'package:newrelic_mobile/loglevel.dart';
    import 'package:newrelic_mobile/newrelic_mobile.dart';
    
    var appToken = "";
    if (Platform.isAndroid) {
      appToken = "ANDROID_APP_TOKEN"; // Replace with your application token copied from the New Relic UI.
    } else if (Platform.isIOS) {
      appToken ="IOS_APP_TOKEN"; // Replace with your application token copied from the New Relic UI.
    }
    
    Config config = Config(
      accessToken: appToken,
      // Optional: (Android only) Enable or disable collection of event data.
      analyticsEventEnabled: true,
      // Optional: Enable or disable reporting successful HTTP requests to the MobileRequest event type.
      networkRequestEnabled: true,
      // Optional: Enable or disable reporting network and HTTP request errors to the MobileRequestError event type.
      networkErrorRequestEnabled: true,
      // Optional: Enable or disable crash reporting.
      crashReportingEnabled: true,
      // Optional: Enable or disable interaction tracing. Trace instrumentation still occurs, but no traces are harvested. This will disable default and custom interactions.
      interactionTracingEnabled: true,
      // Optional: Enable or disable capture of HTTP response bodies for HTTP error traces and MobileRequestError events.
      httpResponseBodyCaptureEnabled: true,
      // Optional: Enable or disable agent logging.
      loggingEnabled: true,
      // Optional: Set the agent log level. The default is LogLevel.WARN.
      logLevel: LogLevel.WARN,
      // Optional: (iOS only) Enable or disable automatic instrumentation of WebViews.
      webViewInstrumentation: true,
      // Optional: Enable or disable forwarding print() output to New Relic as logs. Applies only when you launch the app with NewrelicMobile.instance.start().
      printStatementAsEventsEnabled: true,
      // Optional: Enable or disable automatic instrumentation of HTTP requests.
      httpInstrumentationEnabled: true,
      // Optional: Enable or disable reporting data using different endpoints for US government clients.
      fedRampEnabled: false,
      // Optional: Enable or disable offline data storage when no internet connection is available.
      offlineStorageEnabled: true,
      // Optional: Enable or disable background reporting functionality. Read by both the Android and iOS agents.
      backgroundReportingEnabled: false,
      // Optional: (iOS only) Enable or disable the new, more stable event system for the iOS agent.
      newEventSystemEnabled: false,
      // Optional: Enable or disable distributed tracing.
      distributedTracingEnabled: true,
    );
    
    NewrelicMobile.instance.start(config, () {
      runApp(MyApp());
    });
    
    class MyApp extends StatelessWidget {
      ...
    }
    ```

    Make sure you paste your application token(s) into `appToken = ""` in the code above. If you deployed your app to both iOS and Android platforms, you'll need to add two separate tokens: one for iOS and one for Android.
  </Step>

  <Step>
    ### (Android-only) Configure your Android app [#configure-android]

    If you have an Android-native app, you'll need make the following changes:

   1. Add the following changes to apply the Gradle plugin:

    If your project is using plugin DSL (Flutter 3.16 or higher), make the following changes:

        1. In `android/settings.gradle`:

        ```groovy
        plugins {
            id "dev.flutter.flutter-plugin-loader" version "1.0.0"
            id "com.android.application" version "7.4.2" apply false
            id "org.jetbrains.kotlin.android" version "1.7.10" apply false
            id "com.newrelic.agent.android" version "7.8.3" apply false // <-- include this
        }
        ```

        2. In `android/app/build.gradle`:

        ```groovy
        plugins {
            id "com.android.application"
            id "kotlin-android"
            id "dev.flutter.flutter-gradle-plugin"
            id "com.newrelic.agent.android"  //<-- include this
        }
        ```

  * Or, if your project is older, you can use the  legacy `newrelic` plugin ID by adding this snippet:

        ```groovy
        buildscript {
          ...
          repositories {
            ...
            mavenCentral()
          }
          dependencies {
            ...
            classpath "com.newrelic.agent.android:agent-gradle-plugin:7.8.3"
          }
        }
        ```

        Apply the `NewRelic` plugin to the top of the `android/app/build.gradle` file:

        ```groovy
        apply plugin: "com.android.application"
        apply plugin: 'newrelic' // <-- include this
        ```
  </Step>
</Steps>

## Track screen navigation [#flutter-navigation]

To record screen navigation, add `NewRelicNavigationObserver` to your `MaterialApp`, `WidgetsApp`, or `CupertinoApp`. When a `PageRoute` is pushed, popped, or replaced, the observer records a `navigation` [breadcrumb](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/record-breadcrumb) with the attributes `methodType` (`didPush`, `didPop`, or `didReplace`), `from`, and `to`.

Give each route a name with `RouteSettings(name: 'Your Route Name')`. Routes without a name are reported as `/`. For `go_router` pages (`MaterialPage`, `CupertinoPage`, and similar), the agent reports the page's child widget and key instead of the route name.

```dart
import 'package:newrelic_mobile/newrelic_navigation_observer.dart';

MaterialApp(
  navigatorObservers: [
    NewRelicNavigationObserver(),
  ],
  // other parameters
)
```

If you use the [`go_router`](https://pub.dev/packages/go_router) package, add the observer to the `observers` list of your `GoRouter`:

```dart
import 'package:go_router/go_router.dart';
import 'package:newrelic_mobile/newrelic_navigation_observer.dart';

final router = GoRouter(
  routes: [
    // your routes
  ],
  observers: [NewRelicNavigationObserver()],
);
```

## Instrument HTTP requests [#flutter-http]

When `httpInstrumentationEnabled` is `true` (the default), `startAgent()` sets `HttpOverrides.global` to a `NewRelicHttpOverrides` instance. It wraps every `dart:io` `HttpClient` in a `NewRelicHttpClient`, which automatically records `MobileRequest` and `MobileRequestError` events and, when `distributedTracingEnabled` is `true`, adds distributed tracing headers to the requests.

Because the agent instruments `dart:io` `HttpClient`, requests made with libraries built on it, such as `package:http` and `dio`, are recorded without any extra code:

```dart
import 'package:http/http.dart' as http;

// Recorded automatically as a MobileRequest event once the agent has started.
final response = await http.get(Uri.parse('https://example.com/searchpage'));
```

### Chain with your own HttpOverrides [#flutter-http-overrides]

`NewRelicHttpOverrides` wraps the `HttpOverrides` that are current when the agent starts. If your app uses its own `HttpOverrides` (for example, to set timeouts or to pin certificates), assign them to `HttpOverrides.global` before you start the agent, so the agent can chain with them:

```dart
import 'dart:io';

class MyHttpOverrides extends HttpOverrides {
  @override
  HttpClient createHttpClient(SecurityContext? context) {
    return super.createHttpClient(context)
      ..connectionTimeout = const Duration(seconds: 15);
  }
}

void main() {
  // Set your overrides first. The agent chains with them when it starts.
  HttpOverrides.global = MyHttpOverrides();

  NewrelicMobile.instance.start(config, () {
    runApp(const MyApp());
  });
}
```

If you must set `HttpOverrides.global` after the agent starts, or if you want to control how the underlying `HttpClient` is created, create `NewRelicHttpOverrides` yourself:

```dart
import 'dart:io';

import 'package:newrelic_mobile/newrelic_http_overrides.dart';

HttpOverrides.global = NewRelicHttpOverrides(
  // Chain with your existing overrides.
  current: MyHttpOverrides(),
);

// Or, provide the HttpClient that the agent wraps.
HttpOverrides.global = NewRelicHttpOverrides(
  createHttpClientFn: (SecurityContext? context) =>
      HttpClient(context: context)..connectionTimeout = const Duration(seconds: 15),
);
```

`NewRelicHttpOverrides` also accepts a `findProxyFromEnvironmentFn` to customize proxy resolution.

### Wrap an HttpClient yourself [#flutter-http-client]

To instrument a single `HttpClient` instead of using `HttpOverrides`, set `httpInstrumentationEnabled: false` in your `Config` and wrap the client in `NewRelicHttpClient`. Start the agent before you send requests.

```dart
import 'dart:io';

import 'package:newrelic_mobile/newrelic_http_client.dart';

final HttpClient client = NewRelicHttpClient(client: HttpClient());
final HttpClientRequest request =
    await client.getUrl(Uri.parse('https://example.com/searchpage'));
final HttpClientResponse response = await request.close();
```

## Read the agent configuration [#flutter-get-config]

`getAgentConfiguration()` returns the `Config` object that you passed when you started the agent. Call it only after the agent has started; if the agent hasn't started, the call throws.

```dart
Config getAgentConfiguration()
```

```dart
final Config config = NewrelicMobile.instance.getAgentConfiguration();
print(config.interactionTracingEnabled);
```

## Redirect debugPrint output [#flutter-debug-print]

`startAgent()` calls `NewrelicMobile.instance.redirectDebugPrint()` for you. After that, Flutter's `debugPrint()` output is also forwarded to New Relic as `DEBUG` level logs, regardless of the `printStatementAsEventsEnabled` setting (which controls only `print()` output). You don't need to call `redirectDebugPrint()` yourself, and calling it more than once has no additional effect.

## Symbolicate Dart errors in Errors Inbox [#symbolicate]

New Relic provides in-browser symbolication for Dart error stack traces to make them human-readable. This symbolicated data is not persistent, but you can export it from the browser to a text file for further debugging. Flutter Dart error symbolication requires a `.symbol` file.

## Troubleshoot HTTP errors [#http-errors]

Missing HTTP data in the UI?

After installing the Flutter agent, wait at least 5 minutes. If no HTTP data appears on the HTTP errors and HTTP requests UI pages, make sure you are not replacing `HttpOverrides.global` inside your Flutter app after the agent starts. If your app needs its own `HttpOverrides`, see [Chain with your own HttpOverrides](#flutter-http-overrides).

## Query Flutter log data [#logs]

New Relic stores your Flutter logs as custom events. You can query these logs and build dashboards for them using this NRQL query:

```sql
SELECT * FROM `Mobile Dart Console Events` SINCE 30 MINUTES AGO
```

For more information on NRQL queries, see [Introduction to NRQL](/docs/query-your-data/nrql-new-relic-query-language/get-started/introduction-nrql-new-relics-query-language/#where).
