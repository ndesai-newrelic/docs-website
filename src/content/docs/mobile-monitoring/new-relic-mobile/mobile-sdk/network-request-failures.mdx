      ## Syntax [#syntax]

```java
NewRelic.noticeNetworkFailure(string $url, string $httpMethod, long $startTime, long $endTime, exception $exception OR enum $networkFailure)
```

      ### Kotlin [#kotlin]

```kotlin
NewRelic.noticeNetworkFailure(
    url: String?,
    httpMethod: String?,
    startTime: Long,
    endTime: Long,
    failure: NetworkFailure?,
)
```

      ## Description [#description]

      The New Relic Android SDK API provides several methods to [track network requests](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/network-request-success/). If a network request fails, you can record details about the failure with `noticeNetworkFailure`. In most cases, place this call inside exception handlers, such as catch blocks.

      Here’s an example of an error listener that uses an error as part of the noticed network failure to New Relic:

      ### Java [#java]

```java
new Response.ErrorListener() {
  @Override
  public void onErrorResponse(Error error) {
    NewRelic.noticeNetworkFailure(badUrl, "GET", System.nanoTime(),
        System.nanoTime(), NetworkFailure.exceptionToNetworkFailure(error));
  }
}
```


      ## Description [#description]

      Manually records a failed network request. Failed requests are requests that fail to receive a complete response from
      the server caused by things like TCP timeouts, SSL failures, connection closures, and more.

      You can identify the duration of the request in one of two ways: pass an `NRTimer`, or pass the `startTime` and `endTime` of the request.

      The overloads that take `traceHeaders` (agent version 7.7.8 and higher) report the failure against a distributed trace that you own. Pass the dictionary returned by [`generateDistributedTracingContext`](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/generate-distributed-tracing-headers-ios) so that the resulting `MobileRequestError` event is reported against that trace instead of one that the agent generates. Cross-platform agents that both make and report the request use these overloads. Native instrumentation does not need them.

      ## Examples [#examples]

      ### Objective-C [#obj-c]

      Here's an example that uses a timer:

```objectivec
NRTimer *timer = [NewRelic createAndStartTimer];
// ... the request fails ...

[NewRelic noticeNetworkFailureForURL:[NSURL URLWithString:@"https://www.newrelic.com"]
                          httpMethod:@"GET"
                           withTimer:timer
                      andFailureCode:NSURLErrorTimedOut];
```

      Here's an example with start and end times, in milliseconds since the Unix epoch:

```objectivec
double startTime = [[NSDate date] timeIntervalSince1970] * 1000;
// ... the request fails ...
double endTime = [[NSDate date] timeIntervalSince1970] * 1000;

[NewRelic noticeNetworkFailureForURL:[NSURL URLWithString:@"https://www.newrelic.com"]
                          httpMethod:@"GET"
                           startTime:startTime
                             endTime:endTime
                      andFailureCode:NSURLErrorTimedOut];
```

      ### Swift [#swift]

      Here's an example that uses a timer:

```swift
let timer = NewRelic.createAndStartTimer()
// ... the request fails ...

NewRelic.noticeNetworkFailure(for: URL(string: "https://www.newrelic.com"), httpMethod: "GET",
                              with: timer, andFailureCode: NSURLErrorTimedOut)
```

      Here's an example with start and end times, in milliseconds since the Unix epoch:

```swift
let startTime = Date().timeIntervalSince1970 * 1000
// ... the request fails ...
let endTime = Date().timeIntervalSince1970 * 1000

NewRelic.noticeNetworkFailure(for: URL(string: "https://www.newrelic.com"), httpMethod: "GET",
                              startTime: startTime, endTime: endTime, andFailureCode: NSURLErrorTimedOut)
```
