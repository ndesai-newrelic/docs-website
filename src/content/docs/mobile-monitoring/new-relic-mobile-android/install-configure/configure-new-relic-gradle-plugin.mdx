The New Relic Gradle plugin extension allows you to configure the behavior of plugin tasks executed during Gradle builds. Create a plugin extension in the Gradle build files that apply the New Relic plugin, then add any of the following configuration options:

<table>
  <thead>
    <tr>
      <th style={{ width: "220px" }}>
        Config option
      </th>

      <th>
        Description
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        `enabled`
      </td>

      <td>
        Master switch for the plugin. Set to `false` to disable the plugin. Default: `true`.
      </td>
    </tr>

    <tr>
      <td>
        `instrumentTests`
      </td>

      <td>
        Controls whether test variants, such as unit test and Android test variants, are instrumented. Default: `false`.
      </td>
    </tr>

    <tr>
      <td>
        `variantMapsEnabled`
      </td>

      <td>
        Generate unique build IDs for each app variant. Build IDs are unique identifiers assigned to each build of your app. They're helpful for tracking specific builds, especially when you have different versions with multiple builds, such as version 1.1.1 build 0.0.1. Default: `true`.
      </td>
    </tr>

    <tr>
      <td>
        `uploadMapsForVariant`
      </td>

      <td>
        Specify which variant build types should report ProGuard maps to New Relic. For React Native apps, this also controls which variant build types automatically upload the JavaScript source map (see `reactNativeSourceMapUploadEnabled`). Default: `Release`
      </td>
    </tr>

    <tr>
      <td>
        `excludeVariantInstrumentation`
      </td>

      <td>
        Exclude specific variants from instrumentation during builds. Default: 'None'
      </td>
    </tr>

    <tr>
      <td>
        `excludePackageInstrumentation`
      </td>

      <td>
        Exclude specific classes whose package name starts with or includes class name patterns from instrumentation during builds. This feature can help when
        encountering sensitive or problematic class data.  Default: 'None'

        Supported when used with Gradle 7.4 and higher.
      </td>
    </tr>

    <tr>
      <td>
        `logInstrumentationEnabled`
      </td>

      <td>
          Replaces Android Util Log Classes with NewRelic Log Method for log reporting
          * Default: `true`

          Supported when used with Gradle 7.4 and higher.
      </td>
    </tr>

        <tr>
      <td>
        `defaultInteractionsEnabled`
      </td>

      <td>
          Set to `false` to disable default interactions for Activities and Fragments.
          * Default: `true`

          Supported when used with Gradle 7.4 and higher.
      </td>
    </tr>

    <tr>
      <td>
        `webviewInstrumentationEnabled`
      </td>

      <td>
          Set to `false` to disable webview instrumentation.
          * Default: `true`

          Supported when used with android agent v7.6.15 and later.
      </td>
    </tr>

    <tr>
      <td>
        `reactNativeSourceMapUploadEnabled`
      </td>

      <td>
          Set to `false` to disable automatic upload of React Native JavaScript source maps during the build.
          * Default: `true`

          Supported when used with android agent v7.8.0 and later.
      </td>
    </tr>

    <tr>
      <td>
        `variantConfigurations`
      </td>

      <td>
          Configure individual variants by name. The variant name can be the full name of the variant, its build type, or its product flavor. For each variant, you can set:

          * `instrument`: Set to `false` to exclude the variant from instrumentation. Default: `true`
          * `uploadMappingFile`: Set to `true` to upload the variant's obfuscation map. Default: `false`
          * `mappingFile`: Path to the map file, as an absolute path or a path relative to the app project directory. Use this only when the map file is outside the standard Android Gradle plugin location, such as with DexGuard. The tokens `<name>` and `<dirName>` are replaced with the variant name and the variant directory name.
      </td>
    </tr>

  </tbody>
</table>

Here are some simple examples showing how to apply plugin configuration options to the agent:

<CollapserGroup>
  <Collapser
    id="app-level"
    title="App-level build.gradle example"
  >
    To configure the plugin with default values:

    ```gradle
    newrelic {
        // use a common buildId for all variants (default: true)
        variantMapsEnabled true

        // Tag and report Proguard maps for these build types (default: Release)
        uploadMapsForVariant("Release")

        // instrument all variants
        excludeVariantInstrumentation("")

        // Exclude sample classes from instrumentation (regexp supported)
        excludePackageInstrumentation("")

        // Enable log instrumentation
        logInstrumentationEnabled true

        // Enable the Default Interaction
        defaultInteractionsEnabled true

        // Enable webview instrumentation
        webviewInstrumentationEnabled true

        // Upload React Native source maps (default: true)
        reactNativeSourceMapUploadEnabled true
    }
    ```

    The same options in the Kotlin DSL (`build.gradle.kts`):

    ```kotlin
    newrelic {
        variantMapsEnabled.set(true)
        uploadMapsForVariant("Release")
        logInstrumentationEnabled.set(true)
        defaultInteractionsEnabled.set(true)
        webviewInstrumentationEnabled.set(true)
        reactNativeSourceMapUploadEnabled.set(true)
    }
    ```
  </Collapser>

  <Collapser
    id="map-uploads-multiple"
    title="Enable map uploads for multiple variants"
  >
    Multiple build types can be specified, separated by commas. For React Native apps, adding `Debug` here also enables automatic upload of the JavaScript source map for debug builds:

    ```gradle
    newrelic {
        // default build types
        uploadMapsForVariant("Release", "Debug")
    }
    ```
  </Collapser>

  <Collapser
    id="map-uploads-disable"
    title="Disable map uploads"
  >
    To disable map uploads entirely, use an empty string:

    ```gradle
    newrelic {
        // disable map uploads
        uploadMapsForVariant("")
    }
    ```
  </Collapser>

  <Collapser
    id="exclude-variants"
    title="Disable instrumentation of debug variants"
  >
    Multiple build types can be specified, separated by commas:

    ```gradle
    newrelic {
        // exclude debug build types and flavors
        excludeVariantInstrumentation("Debug", "QADebug")
    }
    ```
  </Collapser>

  <Collapser
    id="exclude-classes"
    title="Disable instrumentation of specific classes"
  >
    You can specificy multiple package patterns, separated by commas, with support for Regexp patterns:

    ```gradle
    newrelic {
        // Don't instrument sample classes
        excludePackageInstrumentation("com.sample", "org.bouncycastle.*")
    }
    ```
  </Collapser>

  <Collapser
    id="disable-log-instrumentation"
    title="Disable log instrumentation"
  >
    To disable log instrumentation:

    ```gradle
    newrelic {
         // disable log instrumentation
        logInstrumentationEnabled false
    }
    ```
  </Collapser>

    <Collapser
    id="disable-default-interactions"
    title="Disable Default Interactions"
  >
    To disable default Interactions for Activities and Fragments:

    ```gradle
    newrelic {
         // disable default interactions
        defaultInteractionsEnabled false
    }
    ```
  </Collapser>

  <Collapser
    id="disable-webview"
    title="Disable Webview Instrumentation"
  >
    To disable webview instrumentation

    ```gradle
    newrelic {
         // disable default webview instrumentation
        webviewInstrumentationEnabled false
    }
    ```
  </Collapser>

  <Collapser
    id="disable-react-native-source-maps"
    title="Disable React Native source map upload"
  >
    To disable automatic upload of React Native JavaScript source maps:

    ```gradle
    newrelic {
        // disable React Native source map upload
        reactNativeSourceMapUploadEnabled false
    }
    ```
  </Collapser>

  <Collapser
    id="variant-configurations"
    title="Configure individual variants"
  >
    To control instrumentation and map uploads for specific variants:

    ```gradle
    newrelic {
        variantConfigurations {
            debug {
                // don't instrument the debug variant
                instrument = false
            }
            release {
                uploadMappingFile = true
                // only needed if the map file is in a non-standard location
                mappingFile = 'build/outputs/mapping/release/mapping.txt'
            }
        }
    }
    ```
  </Collapser>
</CollapserGroup>
